what it does differently

Tiny, and held there

About 3 MiB and 2 ms to start, measured on every run against a ceiling of 8 MiB and 5 ms. A build fails when either is crossed, and the argument and configuration paths never load the agent runtime.

Model and provider agnostic

Any OpenAI-compatible endpoint, the Responses API, Anthropic, or one you name yourself. Connect it once and it is remembered.

Every decision names its source

A limit, a permission, a setting: each one reports where it came from, so rune permissions and rune config answer the question rather than restating the value.

Sandboxed execution

Commands run under the platform sandbox where one exists, so an agent cannot write outside your workspace. rune doctor reports what your host can enforce.

Sessions you can resume

Every turn is written as it runs. Interrupt anything and pick the session back up, or copy a damaged one into a new one rather than losing it.

Local by default

Sessions, usage, and credentials stay on your machine. --offline refuses every outbound request, and a test proves it makes none.

the surface

CommandWhat it does
runeStart an interactive session.
rune ask "..."One request, prints the answer. Pipe it, script it, read it as JSON.
rune reviewReview the pending changes in this repository.
rune resume lastContinue the most recent session in this workspace.
rune connectChoose from a list of providers, then paste a key. Run it again to add more.
rune permissionsSee the rules, and why one of them decided what it did.
rune doctorCheck what this machine supports.
rune acpServe the Agent Client Protocol so an editor can drive a session.

Custom slash commands live in .rune/commands/*.md in a repository, so a team can ship a workflow alongside the code.

What this demonstrates. The shape of the harness around the model: each step picks one tool, every call passes a permission gate before it runs, and the result goes back to the model as the next step's input. It does not demonstrate model quality. The smallest models that run in a tab are weak assistants, and the transcript will look like it.

Chrome's built-in model. Chrome downloads the model itself, once per profile, and keeps it. This page never transfers it. Google does not publish its size and it differs per platform, so this page shows the progress the browser reports rather than a number. It runs on desktop only: Windows, macOS, Linux, or a Chromebook Plus, with at least 22 GB free on the disk holding your Chrome profile, and either a GPU with more than 4 GB of VRAM or 16 GB of RAM with 4 or more CPU cores.

The downloaded fallback. Where the built-in model cannot run, the page offers @wllama/wllama, a WebAssembly build of llama.cpp, loaded from a CDN on click only, plus one quantized model served by Hugging Face. Your browser caches both, so a second visit reads them from disk rather than the network. The 105 MB model is a chatbot, and its own model card scopes function calling to a larger variant. The 398 MB model is the smallest that advertises tool calling. Both are offered because they are what fits, not because either is a good assistant; expect the loop to repeat itself or miss the answer, which is the honest result of running a harness on a model this small.

Nothing is sent anywhere. The prompt runs on your device. This page has no analytics, no account, and no server of its own. It fetches nothing at all until you press a button, which you can check in the network panel.
